# relation-graph · 人际关系图谱

把你身边的人际与利益关系沉淀成一张**可查询、可推理**的图。

**按圈子分开管理** —— 公司圈、同学圈、老家亲戚圈互不干扰。同两个人在公司圈是"竞争",
在同学圈可以是"死党",各记各的,但全库只有一条人员记录。

它要回答的不是"画得好不好看",而是四个具体问题:

1. **谁和目标 X 有矛盾,并且我拉拢得动?**
2. **这里实际存在几个圈子,各自的核心是谁,谁在骑墙?**
3. **谁是绕不开的桥梁人物?我要接触某人,该托谁引荐?**
4. **哪些三角关系是不稳定的 —— 也就是局势最容易翻转的支点?**

跑在自己的电脑上,数据只存本地,手机通过浏览器访问,可"添加到主屏幕"当 App 用。

## 跑起来

**环境要求:** Python 3.9+,没有其他必需依赖。

```
git clone https://github.com/jaykuo6781-bit/relation-graph.git
cd relation-graph
python server.py
```

Windows 上也可以直接双击 **`run.bat`**。

> **双击后闪一下就"服务已停止"?**
> 多半是被 Windows 自带的那个假 `python.exe` 挡住了 —— 系统在
> `%LOCALAPPDATA%\Microsoft\WindowsApps\` 下放了一个 **0 字节的应用执行别名**,
> 运行它不输出任何东西、还返回成功,于是服务静默起不来,连报错都看不到。
>
> `run.bat` 已经会自动跳过它(不看退出码,而是看它有没有真的打印出东西),
> 并且会打印实际使用的 Python 路径。如果它报告找不到可用的 Python,
> 按提示去「设置 → 应用 → 高级应用设置 → 应用执行别名」把 `python.exe`
> 和 `python3.exe` 关掉即可。

打开 <http://127.0.0.1:8787> 就能用了。第一次进去可以在「设置」页点
**载入演示数据** —— 一个虚构的公司圈(19 人)加同学圈(8 人),
里面预埋了派系、引荐链和一组情敌关系,拿它试各个功能最快。

## 在手机上用

### 方式一:Tailscale(推荐)

只有你自己的设备能连,而且在外面用手机流量也能连。

1. 电脑装 [Tailscale](https://tailscale.com/download),登录
2. iPhone / Android 也装,**登录同一个账号**
3. 电脑上正常启动 `python server.py` —— 它会自动检测到 Tailscale 地址并打印出来
4. 手机浏览器打开那个地址

> **Windows 用户注意:第一次多半会连不上,是防火墙拦的。**
> Windows 防火墙默认拦截入站连接,而 Python 安装时创建的放行规则通常只覆盖
> Public 配置文件 —— 偏偏 Tailscale 网卡被归为 Private。表现是:电脑上
> `127.0.0.1` 一切正常,手机却一直转圈。
>
> 用**管理员身份**打开 PowerShell,在项目目录执行一次即可:
>
> ```powershell
> .\setup-firewall.ps1
> ```
>
> 这条规则只放行 TCP 8787,且只接受来自 `100.64.0.0/10`(Tailscale 地址段)
> 的连接 —— 局域网和公网依然进不来。撤销:
> `Remove-NetFirewallRule -DisplayName "relation-graph (Tailscale only)"`

### 方式二:局域网(临时用)

手机和电脑连同一个 Wi-Fi 即可,但**同网络的其他人也能访问**。

```
python server.py --lan          # Windows 上是 run-lan.bat
```

启动时会打印手机该访问的地址。**在公司网络下不要用这个模式。**

### 添加到主屏幕

Safari 打开后 → 底部「分享」→「添加到主屏幕」。
之后从桌面图标进入是全屏无地址栏的,和原生 App 基本没有区别。

## 为什么手机不发热

这是这个项目在架构上唯一"讲究"的地方。

关系图最耗电的部分是**力导向布局的迭代计算**。常规做法是在浏览器里跑物理
模拟循环 —— 每秒几十帧、反复计算每个节点的受力,这正是手机发烫的原因。

这里把这一步整个搬到了电脑端:

```
电脑
 ├── 力导向布局迭代      → 算出每个节点最终的 (x, y)
 ├── Louvain 社区发现    → 派系归属
 ├── Brandes 中介中心性  → 桥梁人物
 ├── Dijkstra 最短路     → 引荐路径
 └── 结构平衡三角扫描    → 不稳定支点
        │
        │  HTTP 返回已经算好的坐标
        ▼
手机
 └── 只做一件事:把坐标画成静态 SVG
     · 没有物理循环,没有逐帧计算
     · 平移缩放只改一个 CSS transform,由 GPU 合成
     · → CPU 基本闲置
```

布局结果按数据版本号缓存,数据不变就不重算;重算时以上一次的坐标为起点,
所以图不会每次大变样,你对它的空间记忆能保留下来。

## 四个分析功能

| 功能 | 算法 | 说明 |
|---|---|---|
| **找敌人的敌人** | 自定义评分 | 对目标 X,找出所有与他有矛盾的人,按 `矛盾烈度 × 可拉拢度` 排序。可拉拢度含你与此人的直接交情,以及经由共同好友的二跳路径。如果某人跟你也不对付,分数会被压到接近零 —— 他不会帮你。 |
| **派系识别** | Louvain 社区发现 | 只用**正向关系**聚类(敌对关系不构成"一伙的")。圈内连接最强的是核心;对外连接占比超过四成的标记为骑墙。 |
| **关键人物 / 引荐路径** | Brandes / Dijkstra | 中介中心性衡量"绕不开"的程度。引荐路径沿正向关系走,边的代价取 `1/强度` —— 交情越铁这一跳越便宜,所以算法优先选强关系链而非单纯的短链。 |
| **不稳定三角** | 海德结构平衡理论 | 三条边的符号相乘为负即不稳定。`++-`(我的两个朋友互相敌视)和 `---`(三人互相敌对)都有内在张力,是局势最可能翻转的地方。按撬动价值排序,并指出撬哪条边最省力。 |

算法全部手写,没有引入图计算库 —— 百来号人的规模下任何算法都是毫秒级的,
手写的好处是"谁值得拉拢"这类评分逻辑完全可控,可以随时按实际情况调。

## 怎么录入

### 底部 AI 输入栏(主要方式)

图谱页底部常驻一个输入框。往里丢东西,AI 把关系理出来给你确认:

| 丢什么 | 说明 |
|---|---|
| **一段话** | "张三和李四为了同一个客户闹翻了" |
| **聊天截图** | 直接截一张微信/群聊丢进去 —— 很多八卦本来就是以截图形式存在的 |
| txt / md / csv | 导出的聊天记录、自己记的笔记 |
| PDF / Word | 需要额外装 `pypdf` / `python-docx`,不装会给出明确提示而不是报错 |

抽出来的每一条都附**原文摘录**,你逐条勾选/修改后才入库,默认落在当前圈子。

一个显著提升准确率的做法:**当前圈子已有的人员名单会一并给模型**,
让它优先匹配已有的人,而不是凭空造出重复节点。

### 批量导入(第一次铺底用)

设置页里可以往当前圈子批量粘人员名单(`姓名,部门,职位`,支持从 Excel 直接复制)
和关系列表(`张三-李四:情敌3`,分隔符很宽容)。

AI 摄取需要配置 `OPENAI_API_KEY` 环境变量(默认用 `gpt-4o-mini`,它支持读图)。
小模型会漏抽也会看错人,所以这个功能的设计前提就是**人工审核**:
每条候选都必须附上原文摘录,你扫一眼就知道它有没有编。
模型调用全部封装在 `llm.py` 一个文件里,换供应商只改这一处。

不配置也完全不影响其余所有功能。

## 数据模型

| 表 | 说明 |
|---|---|
| `circle` | 圈子:公司圈 / 同学圈 / 家族圈… |
| `person` | 姓名、别名、部门、职位、标签、备注,以及"我是谁"的标记。**全局唯一** |
| `person_circle` | 谁属于哪些圈子(多对多) |
| `relation` | 关系:`(圈子, a, b, 类型, 强度)`,强度 −3..+3 |
| `event` | 随手记的事件,作为关系的证据 |
| `event_relation` | 事件与关系的关联 |
| `layout_cache` | 布局与分析结果的缓存,按图版本号失效 |

**关系类型(六大类)**

| 类别 | 类型 |
|---|---|
| 情感 | 情侣、暧昧、好感、单恋、前任、**情敌** |
| 利益 | **利益往来**、合作、金钱借贷、竞争、利益冲突 |
| 职场 | 上下级、同事、师徒、提携、派系盟友 |
| 社交 | 朋友、死党、点头之交、敌对、宿怨 |
| 学缘 | 同学、室友、师生 |
| 亲缘 | 家人、亲戚 |

强度与类型是**互相独立**的两个维度 —— "竞争关系但私交不错"这种情况真实存在,
所以 `竞争 +1` 是合法的。同一对人也可以同时存在多种关系(既是上下级又是竞争),
图上会把它们的强度加总后作为这条边的综合权重。

无向关系统一按 `a_id < b_id` 归一化存储,所以不会出现"张三→李四"和
"李四→张三"两条重复边。有向关系(师徒、提携、上下级、单恋、金钱借贷)
保持 a→b 的语义 —— a 是师傅/上级/暗恋者/出借方。

从旧版本升级会自动迁移:存量关系归入一个默认圈子,旧的类型名
(盟友/同乡同学/利益共同体/认识)自动映射到新词表,一条不丢。

## 自检

```
python selftest.py
```

`demo_seed.json` 里的关系不是随手编的:它预埋了**已知的派系结构**、
**已知的引荐路径**和**已知的不稳定三角**,以及一组**跨圈子对照**(同两个人在公司圈和同学圈里
是不同的关系)。见该文件的 `_expected` 字段。
自检脚本拿这些预设值当标准答案逐条核对,而不是"程序没报错就算过"。

测试跑在临时数据库上,不会碰你的真实数据。

## 技术选型

刻意做成**零构建**:后端只用 Python 标准库(`http.server` + `sqlite3`),
前端是原生 JS + SVG,不用 npm、不用打包工具、不用框架。

理由:这是要长期跑在个人电脑上的私人工具。依赖越少越不会因为环境变动而烂掉,
双击一个 `.bat` 就能起来,三年后再打开大概率还能直接跑。
唯一的可选依赖是 `openai`,只有故事解析功能才需要。

**颜色不够用,所以类别不用颜色。** 图上要同时表达派系、关系正负、关系类别
三件事,全塞进颜色必然糊,而且过不了色觉障碍校验(分类色板在"任意两点
可能相邻"的场景下只有 3 个槽位可用)。所以:

| 维度 | 编码通道 |
|---|---|
| 关系正负 | **颜色** —— 蓝↔红发散色板(不用红/绿,那是最典型的色觉障碍陷阱) |
| 关系强度 | 线宽 |
| 关系类别 | **中点标记符** ♥情感 ¥利益 ▪职场 ●社交 ✎学缘 ⌂亲缘 |
| 负向关系 | 额外加虚线 —— 第二重编码,不靠颜色也能分辨 |
| 派系 | 节点填色(前三大派系上色,其余中性灰) |
| 关键人物 | 节点大小(中介中心性) |

深浅两套皮肤各自跑过配色校验脚本。

**发光效果用 SVG 径向渐变画的同心光晕,不用 `filter`。** iOS Safari 上
`filter` / `backdrop-filter` 极慢,用它做发光会把服务端算布局省下来的
功耗全赔进去。动效也只碰 `opacity` 和 `transform` —— 这两个走 GPU 合成。

## 文件结构

```
server.py        HTTP 路由 + 静态文件服务
db.py            SQLite 存储层
analysis.py      四大分析算法
layout.py        力导向布局计算 + 缓存

```
